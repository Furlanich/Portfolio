Rulings
1. **Helper not used.** The plan's D4 exception lets the lead do the mechanical part inline when no suitable helper can be spawned. Luna (`gpt-6-luna`) cannot be spawned from this runtime, and a Sonnet 5.5 worker is the lead's own model, so it would add a handoff, a worktree and a second context with no cost advantage (the D4 cost argument is that the helper is cheaper). The capture, encoding and derivatives are deterministic scripts. Cost if wrong: none to correctness; the owner's permission to delegate was not exercised.
2. **One composition for both routes.** The scene and its graph are shared by Services and Projects, so the two posters are the same composition at the same pose (they differ only in sub-pixel idle angle, hence the 116256 against 116052 bytes). The manifest keeps four files by route and quality because Task 2 defined it that way. Cost if wrong: re-capture one route at another pose; the owner may want visibly different variants.
3. **Pose.** Progress 0.60 and idle angle 0.50 rad: at 0.40 the network reads half-built with isolated tracer dots, at 0.80 it is dense behind the hero; 0.60 is the first state where most connections are grown and every node is in frame. Cost if wrong: re-run the script with another constant.
4. **Pinned ratio.** `aspect-ratio: 1599 / 900` on the dossier image. Without it a loaded derivative replaces the reserved box by the image's own ratio (640×360 is 1.7778, the original 1.7767), which moved the text below each image by about one pixel in the Projects baselines and is a small layout shift. Cost if wrong: remove the declaration and accept the shift.
5. **Plain `<img>` with `srcSet`.** The bundled Next.js documentation says `next/image` does not forward `srcSet`, and the static export is `unoptimized`, so the responsive candidates had to be listed by the page. The packet's "picture selection" is met with `srcset` and `sizes` on one `<img>`; the Ground keeps its Task 2 CSS selection (a background image the browser fetches once, at the 768px boundary), which satisfies "selects the wide or compact poster at the 768px boundary" without a second mechanism. Cost if wrong: wrap in `<picture>`.
6. **Out-of-set edits, approved by the owner on 2026-10-12.** `scripts/projects-publication.test.mjs` pinned `public/projects` to exactly the two originals and `scripts/project-details.test.mjs` asserted the `next/image` import; both are Task 3 files and neither is in the Task 8 write set. Each edit is one narrow assertion, dated in a comment, and the `aspect-ratio` declaration is one line. Cost if wrong: revert them and rework the wiring.
7. **Node look, by the owner's direction (2026-10-12).** Each node is a flat white dot (radius 0.14, Bone `0xf9f6ee`) inside one thin outer ring (centreline radius 0.39, thickness 0.03, light `0xcfe2f5`), turned to face the camera, on every tier, as Home's markers are. The blue faceted sphere, the tilted ring and the wide second orbit are gone, and so is the `cores` role: the dot is the node. Because the approved motion says nodes and rings rotate slowly at rest (1 to 1.4 degrees per second) and a flat dot and ring show no rotation, a small bead rides the ring at the node's rotation angle: this is my choice, to keep the approved rest motion visible, and it is the first thing to look at in review. The ring is smaller (44 / 38 / 30 px against 80 / 66 / 46), the label anchor still uses the ring radius, draw calls are unchanged at seven, and DESIGN-SPF-V1 carries a dated owner amendment instead of an edit to its history. Cost if wrong: retune the constants, or drop the bead and accept a still node (the rest-rotation requirement then needs an owner decision).
8. **Start pose, by the owner's direction (2026-10-12).** The controller takes an optional `startPose` (`CONNECTED_POSTER_POSE`, one definition in the media manifest that the host and the capture script both read). The first live frame carries it, then the progress eases to the scroll pose with a 0.5 s time constant (the normal damping is 70 ms, so the network visibly settles rather than snaps), ending after 3 s. It is spent once: Pause, Resume, a hidden tab and a Footer round trip never replay it, an invalid pose (non-finite or progress outside 0 to 1) is ignored, and a layout change while it settles keeps easing instead of snapping (a RED found it: a re-measure after fonts and images would otherwise cancel the pose almost immediately). The rotation carries on from the start angle. Two Task 7 runtime tests that assumed an instant rest were adjusted with an `expectSettled` helper, and the idle connection-growth assertion became `< 0.01` because settling approaches 0 asymptotically. Cost if wrong: remove the `startPose` line in the host (one line) or retune the constant.
9. **Posters captured from the first live frame.** With the start pose the poster is the live scene's own first frame, so the capture no longer scrolls or waits for an angle: it holds time with Playwright's fake clock and reads the pose back (progress 0.600000, idle angle 0.500000). `clock.install()` alone leaves time flowing, so `pauseAt` is required, and a held clock never fires `requestAnimationFrame`, so the capture does not wait for one. The capture hides the published poster layer, which sits under the canvas and would otherwise bake the previous poster into the new one. Cost if wrong: re-run the script.
