Rulings (Task 5): (1) Label anchor contract: `xPx` is the label's horizontal centre and `yPx` its top edge, just under the node's ring (ring radius in px plus 6 px); `inView` is true when the node centre is in front of the camera and inside the viewport. The frozen contract only said "projected upright label positions"; cost if wrong: Task 7 applies its own offset (a visible double offset) or changes one constant (`LABEL_GAP_PX` in `connected-labels.ts`). (2) `createConnectedScene(options, factories?)` takes an optional second argument holding the injected canvas and renderer factories (defaults are the real DOM and `WebGLRenderer`); the first argument is exactly the interfaces-map contract. Cost: none for callers that pass one argument. (3) Init failure throws a plain `Error` ("connected-studio: scene initialization failed (…)") after releasing the partial resources, the renderer, its context and the canvas, because `SceneHandle` is non-nullable and cannot signal failure; the host's try/catch stays static. Incoherent options (unknown tier, graph/quality/tier disagreement) throw before any allocation. Once a handle exists no method throws. Cost if wrong: a host that wants a non-throwing init needs a contract change. (4) A renderer that throws while drawing is treated as a lost context: the scene stops and calls `onContextLost` once, which makes the host suppress connected routes for the session (PC-5). Cost if wrong: one transient render error would end live backgrounds for the session; the alternative (swallowing it) would loop failing draws. (5) `resize` ignores unusable input (non-finite or non-positive size, unknown tier, a graph whose quality disagrees with the tier) and keeps the last good layout, and a failed graph rebuild keeps the running scene; the new graph is built beside the old one and swapped only on success. Cost: a host that mis-sizes gets no error. (6) The pixel ratio floor is the device value when below 1 (it is not raised to 1), and an invalid ratio becomes 1. (7) `words` is accepted for contract compatibility but not used: labels are host DOM text, and the engine builds no label or font texture. Cost: none. (8) The engine tags what it builds with `userData.connectedRole` (and `connections` on the path and skeleton batches) so tests and diagnostics can count nodes, rings and connections without reading coordinates; never visible to a visitor. (9) Tracers ride the tip of a connection only while it grows (0 < growth < 1) and are packed from the front of an instanced mesh whose `count` is trimmed, so an idle or complete network draws none and costs no draw call; the complete Footer-state network therefore has no beads. Cost if wrong: the owner wants beads on complete paths (one condition in the update). (10) Light cores do not rotate with the body, so they stay readable; cost if wrong: the owner wants them to orbit (one matrix line). (11) BatchedMesh was evaluated and not used: it batches static geometries with per-instance transforms, while every connection changes shape each frame (bend and growth), so one dynamic merged `BufferGeometry` per layer (16 segments × 5 sides per connection, rewritten per render) is the equivalent single draw call with no multi-draw dependency. Cost: CPU rewrites about 2,800 vertices per render (33 connections × 17 rings × 5 sides); not measured in this PR (Task 9). (12) No bundle or timing claim is made: the optional-closure bytes (≤120 KiB Brotli) and frame times belong to Tasks 7 and 9, and SwiftShader numbers are design evidence only. (13) The engine imports only named exports from `three`; the repository `@ts-expect-error` convention covers the `.ts` runtime imports Node's loader needs.
